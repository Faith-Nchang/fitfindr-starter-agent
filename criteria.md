# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
I chose 4 of 5 because the search depends on how well the user's wording matches the listing data, so some valid queries may fail to find a result even when a similar item exists.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
I chose 5 of 5 because this branch is controlled by deterministic code. If the search returns an empty list, the agent should always stop before calling the next tool and give the user a useful message.

---

## 3. Something about state

Given a query that matches at least one listing, the value stored in
`session["selected_item"]` is the same listing that is passed into
`suggest_outfit` in 5 of 5 tries.

**Why this target:**
I chose 5 of 5 because passing the selected item through session state is
deterministic. If a different item reaches `suggest_outfit`, that would indicate
a problem with how state is being stored or retrieved.

---

## 4. Something about the fit card

For at least 4 of 5 successful runs, the fit card returns a non-empty caption
that clearly refers to the selected item or the outfit created for it.

**Why this target:**
I chose 4 of 5 because the fit card is generated by a model, so the wording can
vary between runs. I still expect the caption to stay relevant to the item and
outfit most of the time.

---

## 5. Your choice

Given a search with a maximum price, every listing returned by
`search_listings` has a price less than or equal to that maximum price in 5 of 5
tries.

**Why this target:**
I chose 5 of 5 because the price ceiling is handled by deterministic filtering
rather than model generation, so the search should respect it every time.
